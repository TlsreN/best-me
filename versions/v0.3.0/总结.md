## 2. 本轮做了什么

### 2.1 应用本体（`app/`）

| 文件 | 作用 |
| --- | --- |
| `index.html` | 外壳：顶栏 + 四个标签页 + 弹层容器 |
| `styles.css` | 全部样式，iPad 双栏 / iPhone 单列自适应 |
| `store.js` | 数据层与计算（纯函数，无 DOM），可移植到原生 |
| `ui.js` | 渲染与交互 |
| `manifest.webmanifest` | 可「添加到主屏幕」，全屏运行 |
| `sw.js` | Service Worker，离线可用 |
| `icon.svg` | 临时图标（你说图标先不搞，这个只是个占位） |

### 2.2 四个页面

1. **今天**：日期翻页、力训日/休息日切换、体重体脂录入、五餐分组的食物列表（含碳/蛋/脂/热量与微量营养素）、四条进度条（热量/碳水/蛋白/脂肪）、训练动作与有氧记录。
2. **日历**：月视图，每天一格；绿=达标、橙=略超、红=超较多，绿框=力训日；点任意一天跳回当天详情。
3. **趋势**：体重 7 日均线 + 单日散点、近 14 天热量柱状图 + 目标线、当日宏量环形图、近 8 周训练容量柱状图。
4. **方案**：增肌/减脂一键切换、个人参数可改、实时算出 BMR→无运动消耗→平衡热量→应吃热量与三大宏量；导出 JSON/CSV、导入备份、清空。

### 2.3 计算口径

与 Excel 表 11 完全一致，已用 22 项断言逐条比对：

- BMR = 9.99×体重 + 6.25×身高 − 4.92×年龄 ± 常数（男 +5 / 女 −161）
- 无运动消耗 = BMR ÷ 0.7
- 力训日平衡 = 无运动 + 力训消耗 + 有氧消耗
- 增肌 ×0.84、减脂 ×0.64
- 碳水 3.5/2.7（增肌）、2.6/2.2（减脂）g/kg；蛋白 1.9 g/kg；脂肪 80/60 g

- `tools/test_store.js`：**22 项全部通过**，含 BMR 1547.54、力训日应吃 2197.4、减脂 1674.2 等与 Excel 逐项对照

- 本地服务器实测：`serve.ps1` 起服务后 HTTP 200，iPad 可通过局域网地址访问

## 4. 踩到的坑（已修）

1. Windows 商店的 `python` 别名会让脚本静默退出 → 改为先用运行时自带的 Python 并实测能跑
2. `serve.ps1` 用 UTF-8 无 BOM 存盘，Windows PowerShell 5.1 读成乱码直接报语法错 → 存为带 BOM
3. 日历在 iPad 上格子被拉到 130px 见方 → 加了最大宽度
4. 训练列表的删除按钮继承了按钮边框 → 单独写了样式

## 5. 已知限制

- 数据在浏览器本地，长期不用有被系统清理的风险 → 方案页提供 JSON 导出，建议每周备份
- 没有 HealthKit，健康数据要靠「快捷指令」导出 CSV 再导入（导入功能待 v0.4.0）
- 食物库还没做，暂时每次手填
- 服务端渲染无，纯前端；部署到静态托管即可

## 6. 下一步（v0.4.0 候选）

1. 部署到免费静态托管（GitHub Pages / Cloudflare Pages），拿到 https 地址，才能在 iPad 上真正「添加到主屏幕」
2. 健康数据导入（CSV 解析 + 去重）
3. 食物库与最近常用，减少手填
4. 计划调整建议（用 docs/03 的规则自动出结论）
