## 1. 本次输入（需求原文）

> 现在我想做一个自己用的软件，首先是 iOS 端的，目的是为了记录我每天饮食情况和健身代谢情况，给出可视化数据，并配有日历记录，由我输入必要的数据来调配训练和饮食计划。在这个项目每次改动和给出要求的时候，都要做一次内容总结，单独创建一个子文件夹，以版本号分类存入。现在告诉我做这个软件需要我准备什么

## 2. 需求解读

一句话：一个**单用户、本地优先**的 iOS 应用，把「吃进去的」「练掉的」「身体变化的」三类数据按天记录下来，用图表和日历回看，并据此让应用给出可执行的训练与饮食调整建议。

拆成四层能力：

1. **记录层**：饮食（食物、份量、热量、蛋白/碳水/脂肪）、训练（动作、组数、次数、重量、有氧时长、心率）、身体（体重、体脂、围度、睡眠可选）。
2. **计算层**：BMR、TDEE、目标热量缺口/盈余、宏量分配、训练容量（tonnage）、代谢适应趋势。
3. **展示层**：日历（每天一格，状态可辨）+ 趋势图（体重 7 日均线、热量收支、宏量环形图、训练容量柱状图）。
4. **计划层**：用户输入目标与约束 → 应用算出本周饮食目标与训练安排 → 用户可手动覆盖。

## 3. 本次产出

《做这个软件需要准备什么》——分三类：

- **硬门槛**：Mac + Xcode + iPhone（+ 可选 Apple Watch / 智能体脂秤）
- **产品决策**：5 个必须拍板的点（自用或上架、数据存放、HealthKit、食物数据来源、计划生成方式）
- **个人数据**：算 BMR/TDEE/宏量所需的体征与目标参数
