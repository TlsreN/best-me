# 09 健康数据导入

## 一、先说清楚限制

**网页应用（PWA）无法直接读 HealthKit。** 这是系统限制，不是没做：

- HealthKit 只对原生 App 开放
- 原生 App 需要 Mac + Xcode 编译，你没有 Mac
- 所以「打开 App 自动同步健康数据」这条路，当前走不通

能走通的是：**iOS 快捷指令读健康 → 写成一行文本 → App 导入**。
半自动：快捷指令可以定时自动跑，但 App 这边仍需你点一次「导入」。

## 二、数据格式

一行一天，逗号分隔，五个字段：

```
2026-11-13,412,1480,8342,35
```

| 位置 | 含义 | 必填 |
| --- | --- | --- |
| 1 | 日期 `yyyy-MM-dd` | 是 |
| 2 | 活动能量 kcal | 是 |
| 3 | 静息能量 kcal | 是 |
| 4 | 步数 | 否 |
| 5 | 运动分钟 | 否 |

头行（`date,active,resting,steps,workoutMin`）可以留，程序会跳过。

## 三、一次性配置快捷指令

> 注意：这个动作在中文 iOS 里叫 **「追加到文本文件」**，不叫「追加到文件」。搜索框输 `追加` 就能看到。

### 最省事的版本（只导活动能量）

四步：

1. **查找健康样本** —— 类型 `活动能量`，筛选 `日期` `是今天`，限制关掉
2. **计算统计信息** —— 输入用上一步，操作从「平均值」改成 **总和**
3. **文本** —— 内容：`[格式日期 今天 yyyy-MM-dd],[统计结果],0,0,0`
4. **追加到文本文件**
   - 文件：点开选 `iCloud 云盘/健康/health.csv`
   - 内容：上一步的文本
   - 如果没有这个动作，看下面的「找不到怎么办」

第三位填 0，App 会用自己算的 BMR 补静息，不影响使用。

### 找不到「追加到文本文件」怎么办

按省事程度排：

**方案 A：每天一个文件**
把第 4 步换成 **「存储文件」**：
- 内容：上一步的文本
- 文件名：`健康-[格式日期 今天 yyyy-MM-dd].txt`
- 位置：`iCloud 云盘/健康/`

App 的导入支持**多选文件**，一次把整个文件夹的文件都选上即可。

**方案 B：走剪贴板**
第 4 步换成 **「拷贝到剪贴板」**。之后打开 App → 健康数据导入 → 长按粘贴框 → 粘贴 → 导入。
缺点：剪贴板会被别的复制覆盖，得当场粘。

**方案 C：完全手动**
跑完快捷指令后，结果会显示在通知里，照着手打一行到粘贴框。一天一次，也不费事。

### 定时

「自动化」→「+」→「时间」→ 每天 23:00 → 运行这个快捷指令 → **关闭「运行前询问」**。

## 四、每天怎么用

- **方案 A（追加）**：快捷指令自己往 health.csv 里加一行；App 里选这个文件导入
- **方案 A'（每天一个文件）**：文件越来越多，App 里多选导入一次全部吃进去
- **方案 B/C**：手动粘贴

导入成功会提示「导入 N 天健康数据」。

## 五、导入之后会发生什么

- 这一天记下 `health = {活动, 静息, 步数, 运动分钟}`
- **总消耗改用「活动 + 静息」**，替代方案里的估算值
- 数据页多一块「消耗与结余」：摄入、消耗、结余，右上角标注「来自健康」
- 没导入的日子仍按方案估算，两者并存

> 注意：总消耗变了，但**目标热量不会自动跟着变**。目标仍按方案参数算，避免一天没同步就把目标带偏。要改目标去「训练与饮食方案」里调。

## 六、以后有 Mac 怎么做

原生版可以直接用 HealthKit：

- 后台自动同步，不用导入
- 能读心率、睡眠、训练明细
- 能耗不再靠估算

那时这套文本格式仍可作为「从旧版迁移」的通道。
