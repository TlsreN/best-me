## 1. 产品概述

**一句话**：给自己用的健身记录本——记下吃了什么、练了什么，用折线和日历看变化，按增肌或减脂方向算好每天该吃多少。

**用户**：本人。男，24 岁，165 cm，63 kg，BMI 23.2，增肌期，午饭前训练，健身房三分化。

**成功标准**（三个月后回看）

1. 连续记录 ≥ 60 天，无中断超过 3 天
2. 单日记录耗时 ≤ 60 秒
3. 能回答「过去 4 周训练容量在涨吗」「这周平均摄入多少」「体重趋势朝哪走」
4. 不必打开 Excel 就能知道今天该吃多少

## 2. 范围

### 做

- 单用户、本地存储、离线可用
- 记录：饮食、身体、力量训练、有氧
- 计算：BMR / 平衡热量 / 目标热量 / 三大宏量，口径与《健身饮食.xlsx》一致
- 展示：一屏首页、日历达标、日/周/月折线
- 自定义食物库（两种计量）
- 导出备份、可迁移

### 不做（首年）

- 账号体系、多设备实时同步、社交
- AI 拍照识别食物、自动生成食谱
- 第三方食物数据库
- 安卓、桌面端、手表独立 App
- 原生 App 与 HealthKit（受限于无 Mac）

## 3. 信息架构

```
最好的我
├── ① 今天          一屏放完，不滚动
│   ├── 顶部条：日期 · 力训日/休息日
│   ├── 能量卡：热量大数字 + 四环（蛋白/碳水/脂肪/饮水）
│   ├── 快捷输入：早饭 · 练前 · 午饭 · 晚饭 · 加餐 · 训练
│   └── 趋势：日/周/月 切换 · 体重折线 · 训练消耗折线
├── ② 数据
│   ├── 日历：月视图 + 每日状态
│   ├── 当日达标：热量 / 蛋白 / 碳水 / 脂肪 / 饮水
│   ├── 自定义食物：每份 或 每 100 g
│   └── 能量换算：kcal ↔ kJ
├── ③ 身体
│   ├── 身体档案：身高 / 年龄 / 性别 / 体脂 / 基础代谢（可编辑）
│   ├── 记录体重：输入 + 最近记录
│   └── 设置：方案 / 备份 / 提醒 / 关于
└── 二级页（从图标进入）
    ├── 记一餐
    ├── 记训练（力量）
    ├── 记有氧
    └── 记录体重
```

**页面归属原则**：今天页只放「今天要看/要记的」；数据页放「要查的」；身体页放「不常改的」。任何卡片必须能回答「为什么不能放别处」。

## 4. 功能规格

### 4.1 今天（首页）

**硬约束：一屏放下，不允许滚动。** 1440×900 与 iPhone 844 高度下均不得出现滚动条。

| 区块 | 内容 | 交互 |
| --- | --- | --- |
| 顶部条 | 日期（11 月 13 日 周五）、力训日/休息日 | 点日期左右翻日；点「力训日」切换，目标立即重算 |
| 能量卡 | 已摄入 / 目标（大数字）、方向胶囊（增肌/减脂） | 只读 |
| 四环 | 蛋白、碳水、脂肪、饮水，各显示 `已摄入 / 目标` 与百分比 | 只读；超 100% 变红 |
| 快捷输入 | 早饭、练前、午饭、晚饭、加餐、训练（6 个） | 点开对应二级页，录完回到首页 |
| 趋势 | 日/周/月 分段控件；两条折线：体重、训练消耗 | 切换范围只重算折线，不跳页 |

**规则**

- 目标按「力训日 / 休息日」两套取值
- 趋势折线横轴：日 = 近 30 天；周 = 近 12 周；月 = 近 12 个月
- 体重折线：日视图叠 7 日均线；周/月视图用该周期均值
- 训练消耗折线：力量 + 有氧合计，可切换只看其一（见 5.5）

### 4.2 数据

**日历**

- 月视图，周一为每周第一天
- 每格显示日期与状态点：达标（≤1.05 倍目标）/ 略超（1.05–1.15）/ 超（>1.15）/ 无记录
- 力训日在格子上加边框
- 点某天 → 下方「当日达标」切到该天；再点一次「进入当天」可跳到首页对应日期

**当日达标**

- 五行：热量、蛋白、碳水、脂肪、饮水
- 每行：`已摄入 / 目标` + 进度条

**自定义食物**

| 计量方式 | 何时用 | 字段 |
| --- | --- | --- |
| 每 100 g | 有营养成分表的工业化食品 | 名称、碳水/100g、蛋白/100g、脂肪/100g、热量/100g（可空自动算） |
| 每份 | 自己做的、按一碗/一盘估算 | 名称、一份叫什么（碗/个/盘）、碳水/蛋白/脂肪/热量（每份） |

- 录入时：每 100 g 类填克数自动换算；每份类填份数（可填 0.5 份）
- 列表按「最近使用」排序，支持搜索
- 删除食物不影响已记录的历史条目（历史存的是快照）

**能量换算**：左右两个输入框，输入任一侧另一侧实时显示，`1 kcal = 4.184 kJ`

### 4.3 身体

| 区块 | 内容 |
| --- | --- |
| 身体档案 | 身高、年龄、性别、体脂（可空）、基础代谢（自动算，只读）；点右上 ✎ 进入编辑 |
| 记录体重 | 数字输入 + 「记录」按钮；下方最近 2 条；「全部」可看历史 |
| 设置 | 训练与饮食方案 › / 数据备份与恢复 › / 提醒 › / 关于 › |

**体重只在这里输入。** 首页的体重曲线读的是这里的数据。日期默认今天，允许补记昨天及以前（最多回溯 30 天）。

### 4.4 二级页：记一餐

**一顿只填一个总数，不拆到每样食物。**

| 字段 | 规则 |
| --- | --- |
| 碳水 g / 蛋白 g / 脂肪 g | 这一顿的合计，手动填 |
| 热量 kcal | 留空时按 `碳×4 + 蛋×4 + 脂×9` 自动算 |
| 备注 | 选填，如「米饭+鸡胸」 |

- 五个餐次各自独立，一天最多五条
- 已记过的餐次再点开就是编辑，底部可「清掉这一餐」
- 不做食物库、不做逐条食物拆分（v3 起取消）

### 4.5 二级页：记训练（力量）

**只填一个总消耗，不记单个动作。**

| 字段 | 规则 |
| --- | --- |
| 总消耗 kcal | 本次力量训练消耗，默认取方案里的「力训日消耗」 |
| 总容量 kg | 选填，`Σ(组×次×重量)`，只用于趋势参考 |
| 备注 | 选填 |

### 4.6 二级页：记有氧

| 字段 | 规则 |
| --- | --- |
| 项目 | 走 / 爬坡走 / 跑 / 骑行 / 游泳 / 球类 / 其他 |
| 时长 | 分钟；不填视为当天没做有氧 |
| 消耗 | `每 kg 每小时消耗 × 体重 × 小时`，自动算 |

力量与有氧在同一个人「记训练」弹层里，各填一条，互不影响。

### 4.8 健康数据导入

**背景**：PWA 读不到 HealthKit，只能靠 iOS 快捷指令导出文本再导入。详见 `docs/09-健康数据导入.md`。

| 项 | 规则 |
| --- | --- |
| 入口 | 身体 → 设置 → 健康数据导入 |
| 输入 | 一行一天：`日期,活动能量,静息能量,步数,运动分钟` |
| 解析 | 跳过表头与坏行；日期必须是 `yyyy-MM-dd`，且至少三段 |
| 合并 | 按日期覆盖（重复导入不叠加） |
| 效果 | 该日总消耗改用「活动 + 静息」，数据页显示「来自健康」与结余 |

**不做**：不自动轮询、不请求网络、不改变目标热量（目标只由方案参数决定）。

### 4.7 二级页：记录体重

数字键盘 + 日期选择（默认今天）+ 保存。

## 5. 计算规范

### 5.1 代谢

```
BMR = 9.99×体重 + 6.25×身高 − 4.92×年龄 + 5        （男）
    = 9.99×体重 + 6.25×身高 − 4.92×年龄 − 161      （女）
无运动消耗 b = BMR ÷ 0.7
力训日平衡 e1 = b + 力量训练消耗 + 有氧消耗
休息日平衡 e2 = b + 有氧消耗
应吃热量 = 平衡 × 0.84（增肌）/ × 0.64（减脂）
```

### 5.2 宏量配额

| 方向 | 碳水（力训/休息） | 蛋白 | 脂肪 |
| --- | --- | --- | --- |
| 增肌 | 3.5 / 2.7 g/kg | 1.9 g/kg | 80 g |
| 减脂 | 2.6 / 2.2 g/kg | 1.9 g/kg | 60 g |

**克数之和 ≠ 目标热量**，原表刻意留 20% 余地，界面上两者都显示，不做配平。

### 5.3 训练消耗（本版新增：力量与有氧分开）

| 项 | 来源 | 存储 |
| --- | --- | --- |
| 力量训练消耗 | 本次力量训练的估算值，可手动覆盖 | `Workout.kcal` |
| 有氧消耗 | 项目×时长×体重 自动算，可手动覆盖 | `Cardio.kcal` |

- 两者**分别记录、分别展示、分别汇总**
- 平衡热量里用「当日合计」
- 趋势折线默认显示合计，可切换只看力量或只看有氧
- 力量训练未记录时，该日按方案默认值（男 新手 150 / 有基础 200 / 老手 250）计

### 5.4 饮水

- 默认目标 2000 ml，可在设置里改
- 首页第四环显示

### 5.5 趋势聚合

| 范围 | 横轴 | 体重取值 | 训练消耗取值 |
| --- | --- | --- | --- |
| 日 | 近 30 天，每天 | 当日体重 + 7 日均线 | 当日合计 |
| 周 | 近 12 周，每周 | 该周有记录日的均值 | 该周有记录日的**日均**消耗 |
| 月 | 近 12 个月 | 该月有记录日均值 | 该月有记录日的**日均**消耗 |

缺失数据不补零，折线断开。

> 消耗一律取「日均」而不是「合计」：否则当前未过完的月份会天然低于整月，折线末端会凭空下跌，看起来像程序出错。访客 2026-11-13 修正（v0.6.2）。

## 6. 数据模型

### 6.1 实体

| 实体 | 关键字段 |
| --- | --- |
| `Plan` | direction、sex、age、heightCm、weightKg、liftKcal、cardioKcal、proteinPerKg、waterMl、bulk{}、cut{} |
| `Day` | key、train、weightKg、bodyFatPct、waterMl、meals{}、lift、cardio、health |
| `Health` | active、resting、steps、workoutMin —— 从快捷指令导入，每日至多一条 |
| `Meal` | carbs、protein、fat、kcal（可空）、note —— 每餐一条 |
| `Lift` | kcal、volume、note —— 每天至多一条 |
| `Cardio` | act、minutes、kcal —— 每天至多一条 |

> v3 把「一条食物一条记录」「一个动作一条记录」合并成「一餐一条」「一次训练一条」。旧数据由 `migrateV2()` 自动汇总。

### 6.2 存储

- 浏览器 localStorage，键 `zghd.v2`（结构变更时升版本号）
- 单个 JSON 对象，导出即整份

### 6.3 兼容规则（新增内容必读）

1. **新增字段必须可选且有默认值**，读取旧数据时由 `normalize()` 补齐
2. **不得删除字段**；废弃的标 `deprecated`，至少保留一个版本
3. 存储键升级（v1→v2）必须提供一次性迁移函数，并在导入时识别旧格式
4. 导出 JSON 带 `schemaVersion`，导入时按版本走迁移链

- 导出 → 导入往返数据完全一致

## 9. 版本与变更流程

### 9.1 版本号

- `MAJOR`：方向性重构（如迁原生、数据模型重做）
- `MINOR`：新增功能域（如新增「自定义食物」）
- `PATCH`：修正、文案、样式微调

### 9.2 每次改动固定六步

1. **改文档**：更新本 PRD 对应章节，或写 `versions/vX.Y.Z/总结.md`
2. **定版本号**：按 9.1 判断
3. **写测试**：涉及计算先加断言
4. **改代码**：只改到刚够用的程度
5. **跑验证**：`test_store.js` 全绿 + 渲染截图 + 对应真机用例
6. **提交**：`git commit` + `git tag vX.Y.Z`，并更新 README 版本表

### 9.3 内容添加规则

| 想加什么 | 必须先回答 |
| --- | --- |
| 新卡片 | 属于哪一页？为什么不能并入现有卡片？删掉会损失什么？ |
| 新页面 | 导航里放哪？怎么返回？首页一屏是否被破坏？ |
| 新字段 | 有默认值吗？旧数据能读吗？导出格式要升级吗？ |
| 新指标 | 计算口径写在 5 章了吗？断言写了吗？ |
| 新图表 | 它能改变什么决策？不能改变决策的不做 |

### 9.4 删除规则

- 先标 `deprecated` 并在界面上保留一个版本
- 下一版再删，删除时同步删断言与文档

### 9.5 发布

- 本地：`tools/serve.ps1`
- 线上：GitHub Pages（待启用）
- 发布前必须过 8.3 全部九条
